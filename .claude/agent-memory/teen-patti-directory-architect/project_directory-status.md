Card grids default to 2-column even on mobile.

- **Content is complete**: all 15 articles (9 guides + 6 posts) exist, each with a `faq` block (renders via `FaqSection`, auto FAQPage schema) and inline `[label](/path)` links (parsed by `ArticleBody`, build-validated in `src/data/articles/index.ts`). Articles never link to specific `/games/[slug]` — only neutral hubs, to avoid implying endorsement. All 9 guides + 6 posts also have a `featuredImage` (from `s-blog-img/webp-blog-img/`, copied to `public/images/blog/<slug>.webp`) used as card thumbnail, detail-page banner, and OG/Twitter/JSON-LD image.
- **Daily promo-code workflow is `promo-code.txt`** (repo root), NOT editing `src/data/games/*.ts` directly. Owner edits this plain pipe-delimited file up to 3×/day (morning/afternoon/evening code slots); `src/data/promo-daily.ts` parses it at build time into `promoDaily` on the matching game, `src/data/games/index.ts` merges it in and auto-upgrades `promoStatus` to `reported-active` when a slot is live. `npm run promo:reset` clears all cells + bumps DATE in one command (recommended daily-reset step, run before entering that day's first code). Parser warns (never throws) on: malformed/missing DATE, stale DATE vs. build date, duplicate/unmatched slugs, codes entered above a missing DATE line, and values that look like a URL/domain instead of a code. **File must currently be blank** (no live codes) as of end of session — that's expected, not a bug.

A small pulsing gold dot on both, plus a separate floating "New promo code / Claim it now" pop-up (`PromoAlert.tsx`, bottom-right, dismissible, `count` prop from `freshPromoCount`), only render when `promo-code.txt` has ≥1 live code — never shown for fake/empty state.
